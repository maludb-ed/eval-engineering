Core of the notes

The 16 trap families

Nearly every wrong option on the exam belongs to one of these families. Learn the tell, the wording that gives the trap away, and you can strike the option before you've finished reading it.

Foundations shapes: T1–T4, T11 Professional shapes: T5–T10, T16 Course patterns: T12–T15
T1

Scale, not strategy

Foundations shape

"Switch to the largest model." "Move to a bigger context window." "Use a bigger embedding model."

Why it's wrong
Size is a knob, not a design. A bigger model doesn't fix auditability, permissions, a stale index, an overloaded prompt or context rot, and it usually makes the cost problem worse.
Right-answer pattern
Change the design at the layer that caused the failure: decompose, trim context, fix retrieval, scope permissions.
Seen in
Every domain. This is the most common distractor on the exam.

Hook: "A bigger container doesn't unsplit a clause."

T2

Knob, not design

Foundations shape

"Lower the temperature." "Raise max tokens." "Retrieve fewer (or more) chunks." "Raise the judge's temperature."

Why it's wrong
It tunes how much a broken design wobbles without fixing the design. Low temperature makes output repeatable, not correct.
Right-answer pattern
A structural fix: examples, decomposition, a better chunking strategy, a deterministic grader.
Seen in
D2 prompting, D3 retrieval, D4 evals, D6 SLAs ("pin temperature to 0 and promise perfection").

Hook: "Repeatable ≠ correct."

T3

Louder, not explicit

Foundations shape

"Add a firmer line insisting the format be exact." "Tell the model never to forget." "Re-present the same diagram with more detail."

Why it's wrong
Emphasis adds no missing information or capability. A model can't attend to what's buried in an overloaded window just because you asked harder, and a committee's unstated objection doesn't go away when you repeat the pitch.
Right-answer pattern
Show rather than tell: few-shot examples, explicit criteria, restructured context, or reframing the pitch for the real constraint.
Seen in
D2 (format drift), D4 (context rot), D6 (rejected proposals).

Hook: "Asking louder for what only an example can show."

T4

Prompt as guarantee

Foundations shape

"Add to the system prompt: never…" "Move the instruction into the tool description." "Add a line to CLAUDE.md."

Why it's wrong
Prompts and instruction files are guidance. They are probabilistic, so they shape what the model probably does. They can't enforce access, spending limits or compliance. A must requirement needs enforcement.
Right-answer pattern
A deterministic check in code, a permission rule, a hook, or access scoped to the requesting user's identity. Prompt-level defenses are a legitimate layer, but never the only control on a must.
Seen in
D5 (payment limits, PII leaving the network), D3 (the HR agent on a shared account), D7 ("a note is not a wall").

Hook: "A prompt asks. Code stops it."

T5

Compliance theater

Professional shape

"Log every call for later audit." "Add a privacy notice." "A manager signs off the weekly log." "More uptime dashboards." "A memo asserting compliance."

Why it's wrong
It detects or documents the problem. It records the harm after it happens instead of preventing it. Verbose logging can even create exposure, for example by writing raw PHI into logs.
Right-answer pattern
A preventive control that blocks the action. For quality problems, a measured signal that pages you.
Seen in
D3 least privilege (official sample 1), D5 compliance, D4 monitoring.

Hook: "A log tells you the barn door was open."

T6

Eval blindness

Professional shape

"It read better in the demo, so ship it." "Watch production for regressions." "Wait for more customer reports." "Drop the verification step to go faster."

Why it's wrong
Without a fixed ruler you can't tell a real regression from noise, and debugging turns into waiting for complaints.
Right-answer pattern
A golden set, a recorded baseline, and a ship gate every change must pass. In production, sample outputs, score them, and alert on drift.
Seen in
D4 throughout, and in the "silent quality drop" autopsy.

Hook: "The demo flatters. The golden set decides."

T7

Wrong-layer fix

Professional shape

Rewriting the prompt when the index is stale. A bigger model when context is overloaded. A coordinator agent to patch a bad split. Enabling caching to fix context rot.

Why it's wrong
It fixes the loudest layer, usually the prompt or model because they're the most visible, instead of the layer that caused the failure. The wrong fix always feels productive.
Right-answer pattern
Diagnose first: What changed? What does the symptom track with? Which layer does that point to? The five suspects are prompt, context, retrieval, model and tooling.
Seen in
D4 diagnosis, and all four autopsies.

Hook: "Stop blaming the loudest layer."

T8

Over-orchestration

Professional shape

"One agent per field / section / report type." "Add a supervisor, coordinator or routing agent." "A separate agent to fetch one number."

Why it's wrong
Coordination replaces work. Every handoff can drop context, latency stacks up, and multi-agent systems burn roughly 15× the tokens of a chat.
Right-answer pattern
One well-contexted agent or a fixed workflow. Split only for context isolation or parallel breadth on work that genuinely separates.
Seen in
D1 multi-agent design, D3 (A2A used for a simple lookup).

Hook: "Every handoff is a place context gets dropped."

T9

Gold plating

Professional shape

"A human reviews every output." "Add a cross-checking model and a full dashboard." "Build an MCP server so future tools can plug in." "Add a model router now."

Why it's wrong
It's the maximum build instead of the minimum that clears the constraint. It adds cost and latency nobody asked for, and a heavier proposal is harder to get approved.
Right-answer pattern
The smallest design that meets every stated constraint, with the trade-off named out loud.
Seen in
D1 (climbing the pattern ladder too high), D5 (reviewing everything), D6 (making the proposal "more impressive").

Hook: "The strongest architecture is usually the smallest one that clears the bar."

T10

Premature optimization

Professional shape

"Rewrite every prompt shorter." "Turn on caching right away." "Switch everything to the smallest model." Each is offered before anyone has measured.

Why it's wrong
You can't optimize what you haven't measured, and this makes risky changes that affect output quality first.
Right-answer pattern
Record a baseline. Take the output-neutral wins first: cache → route → batch. Change quality-affecting settings (prompt, model tier, context) last, one at a time, with an A/B test.
Seen in
D4 cost optimization. The buried clue is "haven't measured where the cost comes from yet".

Hook: "Free wins first. Risky wins last, and tested."

T11

Convenience over safety

Foundations shape

"Grant broad write access so it never hits a permission error." "Widen the shared allow rules to stop the prompts." "Give it a general web tool." "Grant prod write access during the incident."

Why it's wrong
It trades a larger attack surface and blast radius for speed. Anything the agent can do, an attacker who controls its input can also do.
Right-answer pattern
Least privilege, and the existing approval and deploy path.
Seen in
D3 integration, D7 (incident response, shared settings).

Hook: "A tool the agent doesn't have is a tool an attacker can't reach."

T12

Answering the stated pillar

Course pattern

"Build the ambitious platform, since the VP asked to transform the team."

Why it's wrong
What someone said out loud isn't necessarily the constraint. Discovery facts such as fixed reports, a modest budget or a stable format point to a different pillar.
Right-answer pattern
Serve the pillar the constraint points to (efficiency, transformation, productivity, cost or a performance target), and name what the choice costs on the others.
Seen in
D1 business value, D6 discovery.

Hook: "Hear 'transformation', architect for efficiency."

T13

Promising determinism

Course pattern

"Guarantee in writing that it will never misclassify." "Promise perfect accuracy by pinning temperature to 0."

Why it's wrong
An LLM system is probabilistic by design, so no configuration can guarantee it is never wrong.
Right-answer pattern
A measured rate on a representative eval set, a p95 latency target, and an escalation path for misses and low-confidence or high-impact cases, reviewed on a schedule.
Seen in
D6 SLAs, D3 accuracy/latency trade-offs.

Hook: "Promise a measured rate and a plan for misses, never perfection."

T14

Self-reported confidence gate

Course pattern

"Have the agent rate its own confidence and only pause for a human when it's unsure."

Why it's wrong
The expensive failure is the model being confidently wrong, and a confidently wrong model reports high confidence, so the gate never fires.
Right-answer pattern
Place the human by risk tier (impact × reversibility), enforced outside the model. Gate irreversible or high-stakes actions and let low-stakes, reversible ones flow.
Seen in
D5 human-in-the-loop.

Hook: "The gate is for the rare time the model is confidently, expensively wrong."

T15

Right rule, wrong scope

Course pattern

"Ask each engineer to add the deny rule to their personal settings." "Copy one senior engineer's setup onto everyone's machine."

Why it's wrong
Per-person configuration is optional and drifts. One engineer who skips it reopens the hole, and copied setups aren't under source control.
Right-answer pattern
Put guarantees in managed policy, which can't be loosened from below. Put shared standards in checked-in project config. Keep personal settings personal.
Seen in
D7 team configuration.

Hook: "Right wall, wrong building."

T16

Stale fact KIT

Professional shape

"Retrieval is mandatory for any document question." "SOC 2 covers HIPAA." Claims that were true on an older platform or under older limits.

Why it's wrong
The platform has moved on (larger windows, prompt caching, Skills, HIPAA-ready access), so the option answers a question from a year ago.
Right-answer pattern
Reason from current capabilities. A small, stable corpus can go straight into the prompt and be cached, with no retrieval pipeline.
Seen in
D3 RAG, D5 compliance.

Hook: "True once isn't true now."

How to use these on exam day: as you read each option, silently label it with its trap number. If three options each get a label, the fourth is your answer. For a multiple-response item, any option you can't label is a candidate.
