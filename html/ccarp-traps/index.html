The one idea behind every trap

Foundations asked

"Can you build it?"

Professional asks

"Should you build it, and can you defend the call?"

You are the architect in the room when someone asks why you didn't pick the cheaper design.

The three-move method

  1. Read for the constraint, not the topic

    The deciding clause is usually buried mid-stem: must, never, guarantee, reproducible, audit, cost ceiling, regulator, no baseline yet. Find it before you look at the options.

  2. Eliminate by principle

    Name the principle the item is testing (least privilege, simplest pattern, must → code, measure first) and strike every option that breaks it. Each wrong option usually maps to one of the 16 trap families.

  3. On multiple-response items, judge each option alone

    Treat every option as a separate true/false against the stem, then select exactly the number the item asks for.

Find the constraint. Name the principle. Pick the option that breaks nothing.

Tie-breaker: the winning option usually removes something or is the simplest design that meets every constraint. It is almost never "use a bigger model" or "add more machinery".
